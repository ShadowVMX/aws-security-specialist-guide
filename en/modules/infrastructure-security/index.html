Advanced edge rules & OCSF (3.1.3 / 3.1.4)

  • Geolocation / rate limiting / client fingerprinting: WAF combines conditions (country, volume, client fingerprint via JA3/JA4 fingerprinting) to block sophisticated bot patterns that rotate IPs.
  • Third-party rules: AWS Marketplace offers managed rule groups from specialized security vendors (in addition to AWS Managed Rules).
  • OCSF (Open Cybersecurity Schema Framework): an open schema that normalizes security events from AWS and third parties into the same format — used natively by Amazon Security Lake to enable correlation without writing a parser for every source.

Hardened AMIs & container images (3.2.1)

EC2 Image Builder automates a pipeline: base image → hardening/config components → patches → tests → published AMI/container image.

Coming from Azure Azure Image Builder is practically the same concept with the same name: a managed pipeline for building hardened, reproducible VM images from a base image plus customizations. One of the most direct mappings in the whole exam.

Instance profiles, service roles & execution roles (3.2.2)

TypeUsed in
Instance ProfileEC2 — a container that associates an IAM Role with the instance; the SDK obtains credentials automatically from the Instance Metadata Service (IMDS).
Service RoleAn AWS service (e.g. Config, CodePipeline) assumes this role to act on your behalf on other resources.
Execution RoleLambda/ECS/Fargate — the permissions held by the running CODE, distinct from the role that deploys the function/task.
Watch out for IMDSv1 vs IMDSv2 IMDSv1 (based on simple HTTP GET requests) is vulnerable to SSRF: a malicious HTTP request relayed by the app can steal the Instance Profile's credentials. IMDSv2 requires a session token obtained via PUT, which most SSRF libraries don't forward — enforce it with HttpTokens=required in the instance's metadata configuration (or via a Declarative Policy at the organization level).

Secure administrative access (3.2.5)

Coming from Azure Systems Manager Session Manager ↔ Azure Bastion: both provide shell access without opening inbound ports (22/3389) or exposing a public IP, with sessions audited centrally. The difference: Azure Bastion is a network resource you deploy in the VNet (with a fixed hourly cost); Session Manager is an agent + managed service with no network resource to provision, and it also works on hybrid (on-premises) instances registered with Systems Manager.

Start a session without SSH or an open port

aws ssm start-session --target i-0123456789abcdef0

Administrative access without opening a single port

# La instancia necesita el SSM Agent y un instance profile con permisos.
aws iam attach-role-policy \
  --role-name EC2SessionManagerRole \
  --policy-arn arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore

# Abrir sesion: sin puerto 22, sin IP publica y sin bastion.
aws ssm start-session --target i-0abcd1234efgh5678

# Sin salida a internet, la solucion son VPC endpoints — no abrir entrada.
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-0a1b2c3d4e5f67890 \
  --vpc-endpoint-type Interface \
  --service-name com.amazonaws.eu-west-1.ssmmessages \
  --subnet-ids subnet-0123456789abcdef0

Pipeline security & GenAI guardrails (3.2.6 / 3.2.7)

  • Amazon CodeGuru Security: static analysis (SAST) of source code in the pipeline — vulnerabilities and hardcoded secrets before deployment.
  • Amazon Q Developer: AI-assisted remediation suggestions integrated into the IDE/pipeline.
Plain-language example — new in SCS-C03 If your application exposes an LLM-based chatbot (e.g. via Bedrock) to end users, the OWASP Top 10 for LLM Applications catalogs risks specific to this space that don't exist in traditional apps: prompt injection (a user manipulates the prompt to bypass the system instructions), leakage of sensitive data in the model's responses, or poisoning of the data used for fine-tuning/RAG. Implementing guardrails (e.g. Amazon Bedrock Guardrails) to filter inputs/outputs is the exam's typical answer to this scenario.

Security Groups vs Network ACLs (3.3.1)

Security GroupNetwork ACL
LevelENI / instanceSubnet
StateStateful (return traffic is allowed automatically)Stateless (both directions must be allowed explicitly)
RulesAllow onlyAllow and Deny, evaluated in numeric order
ScopeALL rules are evaluated (no order)Stops at the first matching rule
Watch out if you're coming from Azure — this is different Azure has a SINGLE construct, the Network Security Group (NSG), which you can associate with a subnet OR a NIC, and which DOES support explicit Deny rules with numeric priority — meaning an NSG behaves a bit like a blend of AWS's Security Group + NACL. In AWS, by contrast, these are TWO separate mechanisms with different behaviors (stateful vs stateless) that ALWAYS apply together (first the subnet's NACL, then the instance's SG). Don't assume "I already have a NACL configured = I don't need a Security Group," or vice versa: in AWS both layers act simultaneously.

The detail people forget: ephemeral ports in the NACL

# Entrada: permitir HTTPS desde internet.
aws ec2 create-network-acl-entry \
  --network-acl-id acl-0a1b2c3d4e5f67890 \
  --rule-number 100 --protocol tcp --port-range From=443,To=443 \
  --cidr-block 0.0.0.0/0 --rule-action allow --ingress

# Salida: SIN esta regla, la respuesta no sale y la conexion parece colgarse.
# Las NACL son stateless: el trafico de vuelta hay que permitirlo a mano.
aws ec2 create-network-acl-entry \
  --network-acl-id acl-0a1b2c3d4e5f67890 \
  --rule-number 100 --protocol tcp --port-range From=1024,To=65535 \
  --cidr-block 0.0.0.0/0 --rule-action allow --egress

# Bloquear una IP concreta: esto un security group NO puede hacerlo.
aws ec2 create-network-acl-entry \
  --network-acl-id acl-0a1b2c3d4e5f67890 \
  --rule-number 50 --protocol -1 \
  --cidr-block 203.0.113.25/32 --rule-action deny --ingress

Choosing hybrid connectivity (Skills 3.3.2 / 3.3.3)

Coming from Azure Direct Connect ↔ Azure ExpressRoute (ExpressRoute Direct also supports MACsec — a very direct mapping). Site-to-Site VPN ↔ Azure VPN Gateway (S2S). No simple 1:1 equivalent: Verified Access is closer to Entra Private Access than to any traditional Azure networking product.

Network segmentation & AWS Network Firewall (3.3.4 / 3.3.5)

  • North/south: traffic that crosses the perimeter (Internet ↔ VPC). East/west: internal traffic between workloads — isolating it reduces the blast radius if a component is compromised.
  • Isolated subnets (no route to the Internet, not even via NAT) for the most sensitive workloads (e.g. databases).
  • AWS Network Firewall: stateful layer 3-7 inspection, domain rules (FQDN), and IDS/IPS-style signatures (Suricata) — more advanced than SG/NACL for transit traffic.
  • Detecting unintended access: Amazon Inspector (Network Reachability) and VPC Network Access Analyzer model the entire SG+NACL+route table chain to find reachable paths that shouldn't exist.
Coming from Azure AWS Network Firewall ↔ Azure Firewall: both are managed layer 3-7 firewalls with domain rules, designed for centralized transit traffic (often sitting behind a Transit Gateway / Virtual WAN respectively).

Classic exam traps

The mistakes that repeat most in this domain. If you're short on time before the exam, review just this and the quiz.

Stateful vs stateless, and ephemeral ports Security groups are stateful: allow inbound and the reply leaves on its own. NACLs are stateless: return traffic must be allowed explicitly, and that is where the ephemeral port range (1024-65535) comes in. A "connection establishes but gets no response" scenario with a NACL involved is almost always this.
Security groups cannot deny A security group has only allow rules: anything not allowed is implicitly denied, but you cannot block a specific IP with it. That's the NACL's job — it supports Deny and is evaluated by rule number, lowest first, stopping at the first match.
WAF is layer 7, Shield is layer 3/4 SQL injection, XSS or bots → AWS WAF. Volumetric floods (SYN flood, UDP amplification) → Shield. If the question mixes both attacks, the right answer usually needs both services, not one.
CloudFront's WAF lives in us-east-1 A web ACL attached to CloudFront is global scope and is created in us-east-1. Those attached to ALB, API Gateway or AppSync are regional and live in the resource's Region. The exam uses this detail to rule options out.
Inspector assesses, it doesn't block Amazon Inspector finds and prioritizes vulnerabilities, but it is not in the traffic path and prevents nothing. If the question asks to stop malicious requests, Inspector is never the answer.
Session Manager needs no inbound ports The session is established by an outbound connection from the agent to the service. No port 22, no public IP and no bastion are needed — but the SSM Agent and an instance profile with permissions are. If the instance has no internet egress, the fix is VPC endpoints, not opening inbound.
